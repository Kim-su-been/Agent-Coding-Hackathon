# DIR — 산출물 접수·검토 보드(outputhub) SoT

## 1. 목적·적용 범위
작업 폴더 `deepwiki/sot`에 두는 프로젝트 정본. PMO가 차수(계약 품의 등)별로 받아야 할 산출물을 미리 등록한 기준대장을 중심으로, 업로드 접수·규칙 기반 매칭·버전 관리·내보내기까지의 요구·표준·용어·시험을 정본으로 관리한다.
근거: 기획 논의(계획 v3 A~E절), 첨부 자료 `.deepwork/attachments/Agent_Instructions-8b78b746e0c0.md`.

## 2. 포함/제외
- 포함: 요구사항정의서(REQ), 표준(코딩 규칙 STD), 용어집(GLO), 시험시나리오(TS), 결정 기록(기록/). 화면정의서·업무설계서는 이후 같은 구조에 추가한다.
- 제외: 코드 본문(경로·심볼·줄 범위로만 가리킨다), 개인정보 원문, 비밀값. 구현 소스는 SoT 밖 저장소에 둔다.

## 3. 배치
| 경로 | 목적 |
|---|---|
| DIR.md | 이 문서. 배치·책임·정본 규칙 안내 |
| 업무/outputhub/ | 산출물 보드 업무의 요구사항정의서·시험시나리오·용어집 |
| 표준/ | 개발 표준(STD-001 코딩 규칙 등) |
| 기록/ | 결정 기록(발생 시 추가) |

## 4. 책임
작성·검토: 개발 담당(해커톤 팀). 팀 승인은 MR·PR 병합으로 한다. [확인 필요: 승인자 지정 · 확인자: 사용자 · 기한: 미정]

## 5. 분리 기준
독립 변경·검토 단위마다 한 문서. 산출물 보드 업무는 REQ/TS/용어집으로, 개발 표준은 STD로 분리한다. 중복 내용은 ID 링크로 연결한다.

## 6. 근거·검증
문서마다 머리말 sources에 근거 경로를 남긴다. 요구는 REQ ID, 인수 기준은 AC ID, 시험은 TC ID로 상호 연결한다. 검증은 sot_lint(머리말·ID 꼴)와 시험 시나리오 실행으로 한다.

## 7. 갱신 조건
요구 추가·변경, 기술 스택·코딩 규칙 변경, 시연 시나리오 변경, 용어 신설 때 해당 문서를 재검토한다.

## 8. 정본·승인
`status`를 쓰지 않았거나 stable인 문서는 이 작업 폴더의 정본이다. draft·deprecated는 정본이 아니다. 팀 공유 정본은 MR·PR로 병합된 문서다.
