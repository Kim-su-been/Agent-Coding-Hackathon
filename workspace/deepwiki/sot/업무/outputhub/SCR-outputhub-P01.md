### 2-4. 상태와 검증

- 로딩·빈 화면·오류·재시도: 로딩 스켈레톤 표시. 차수가 없으면 "차수를 먼저 등록하세요" 빈 화면. API 오류 시 오류 배너 + 다시 시도 버튼.
- 권한별 표시(ROLE): PMO 단일 역할(D-001)이라 모든 동작 노출. 향후 다중 역할 시 확정·승인·보완 지정은 PMO 전용으로 숨김 처리 필요.
- 입력 검증(화면 형식 검사 / 서비스 업무 검사 분담): 화면은 차수 선택 필수만 검사. 상태 전환 가능 여부는 서비스 업무 검사(확정은 접수 상태만).
- 접근성: 상태는 색상 배지 + 텍스트 라벨 병행(색만으로 구분하지 않음). 표 헤더 scope 지정.

- 입력 검증: 파일 0개 업로드 차단, 허용 확장자·최대 크기는 설정 파일 값 사용(REQ-outputhub-014) [확인 필요: 허용 확장자·최대 크기 값 · 확인자: 개발 담당 · 기한: 미정].
