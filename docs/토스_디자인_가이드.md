# 토스(Toss) 디자인 가이드

> 토스가 공개한 자료(토스 디자인 `design.toss.im`, 토스 브랜드 `brand.toss.im`, 토스 기술 블로그 `toss.tech`)를 바탕으로 정리한 참고용 가이드입니다.
> 최신 수치·토큰이 필요하면 원문 자료를 우선하세요. 프로젝트에서는 이 문서의 값을 디자인 토큰(상수)으로 정의해 일관되게 사용합니다.

---

## 1. 핵심 원칙 — 4가지 브랜드 가치

토스의 모든 화면·컴포넌트·문구는 아래 4가지 가치로 판단합니다.

| 가치 | 한 줄 정의 | 화면에서의 적용 |
|---|---|---|
| **명확하게** (Clear) | 누가, 어디서 보든 같은 의미로 이해되게 | 용어·형태를 일관되게, 장식보다 정보 우선 |
| **편리하게** (Useful) | 가장 가려는 곳에 가장 빨리 도달하게 | 단계 최소화, 자주 쓰는 기능 먼저 |
| **넉넉하게** (Generous) | 여백과 크기를 아낌없이 | 넉넉한 그리드·여백, 충분한 터치 영역 |
| **긍정적으로** (Optimistic) | 겁주지 않고 안심시키는 표현 | 경고 대신 안내, 밝고 가벼운 톤 |

## 2. 색상 (Color)

### 2.1 회색조 — 텍스트·배경의 기준

| 토큰 | HEX | 주 용도 |
|---|---|---|
| grey900 | `#191F28` | 본문·강조 텍스트 |
| grey700 | `#4E5968` | 보조 텍스트 |
| grey500 | `#8B95A1` | 안내 문구·플레이스홀더 |
| grey400 | `#B0B8C1` | 비활성 텍스트·아이콘 |
| grey200 | `#E5E8EB` | 경계선(보더) |
| grey100 | `#F2F4F6` | 연한 배경·보조 버튼 배경 |
| grey50 | `#F9FAFB` | 화면 배경 |

### 2.2 강조색

| 토큰 | HEX | 주 용도 |
|---|---|---|
| blue600 (Primary) | `#3182F6` | 주요 버튼·링크·활성 상태 |
| blue50 | `#E8F3FF` | 파란 강조 배경·배너 |
| red600 | `#F04452` | 경고·오류·위험 동작 |

### 2.3 사용 규칙

- 텍스트 위계는 "진한 회색 → 연한 회색"으로 만든다. 색을 늘리기보다 **명도로 구분**한다.
- Primary 파랑은 한 화면에서 **가장 중요한 동작 하나**에만 집중한다.
- 경고·오류는 빨강(`#F04452`)으로 통일하고, 표현은 부드럽게 한다.
- 화면 배경은 밝은 회색(grey50~100), 카드·시트·모달은 흰색(`#FFFFFF`).
- 모달·바텀시트 뒤는 반투명 검정 딤(약 40%)으로 가린다.
- 색상은 코드에 직접 쓰지 않고 토큰(변수)으로 관리한다.

## 3. 타이포그래피

- 서체는 시스템 기본 폰트를 기준으로 한다(iOS: SF Pro / Apple SD Gothic Neo, Android: Roboto / Noto Sans KR). 토스 자체 서체(토스페이스) 사용 여부는 `brand.toss.im`에서 라이선스를 확인한다.
- 행간(줄 높이)은 글자 크기의 1.4~1.6배.
- 굵기: 제목 Bold(700), 본문 Regular(400), 강조 SemiBold(600).

| 스타일 | 크기 / 행간 | 굵기 | 용도 |
|---|---|---|---|
| title1 | 24px / 34px | Bold | 화면 최상단 큰 제목 |
| title2 | 22px / 30px | Bold | 섹션 제목 |
| title3 | 20px / 28px | Bold | 카드·시트 제목 |
| subtitle | 18px / 26px | Bold | 소제목 |
| body1 | 17px / 26px | Regular | 기본 본문(핵심 정보) |
| body2 | 15px / 22px | Regular | 보조 본문·리스트 |
| caption | 13px / 20px | Regular | 캡션·메타 정보 |
| micro | 12px / 16px | Regular | 탭 라벨·배지 |

- 금액·숫자 등 핵심 값은 **크게 + Bold**, 부가 설명은 작게 — 크기 대비로 위계를 만든다.
- 본문 텍스트는 grey900/grey700을 기본으로 하고, grey500은 플레이스홀더·보조 안내까지만 사용한다(명암 대비 확보).

---

## 4. 레이아웃·간격

- 기본 단위는 **4px**. 간격은 4의 배수(8, 12, 16, 20, 24, 32, 40)만 사용한다.
- 화면 좌우 여백은 **24px**(모바일 기준)로 통일한다.
- 관계가 가까운 요소는 가깝게, 다른 그룹은 크게 띄운다(근접성).
- 리스트 아이템 내부 여백은 16px 수준, 섹션 사이는 32px 수준.
- 핵심 동작(CTA)은 하단 고정 영역에 두어 한 손으로 항상 닿게 한다.

---

## 5. 컴포넌트

### 5.1 버튼

- **Primary**: 파란 배경(`#3182F6`) + 흰 텍스트. 한 화면에 하나만.
- **Secondary**: 연회색 배경(`#F2F4F6`) + 진회색 텍스트.
- **위험 동작**(해지·탈퇴 등): 빨간 배경 또는 빨간 텍스트.
- 높이: 주요 CTA 52~56px, 보조 44~48px. 모서리 반경 8~12px로 통일.
- 라벨: 16~17px SemiBold, "다음 / 확인 / 저장"처럼 **결과가 분명한 짧은 동사**.
- 비활성 상태는 회색 배경 + 회색 텍스트로 명확히 구분.

### 5.2 입력창

- 테두리 없이 **밑줄(하단 보더) 스타일**을 기본으로 한다. 입력 중에는 밑줄이 파란색으로 활성화.
- 라벨은 입력값 위에 작게, 오류 메시지는 빨간색으로 필드 바로 아래에 둔다.
- 키보드 종류(숫자 패드 등)를 입력 형식에 맞게 지정한다.

### 5.3 모달·바텀시트

- 단순 확인(예/아니오) → **중앙 모달**, 폼·선택 목록 → **하단 바텀시트**.
- 바텀시트: 상단 모서리 반경 12~16px, 위로 끌어올려 닫는 제스처 지원.
- 모달 문구 3요소: 제목(무엇을 묻는지) + 본문(이유) + 버튼(결과가 보이는 라벨).

### 5.4 토스트

- 화면 하단 중앙, 어두운 배경 + 흰 텍스트, 모서리 반경 8px 내외.
- 2~3초 노출 후 자동 사라짐. 성공·실패 결과는 즉시 토스트로 알린다.

### 5.5 리스트·카드

- 흰 배경 카드, 모서리 반경 12~16px, 클릭 가능한 카드는 눌림 피드백 제공.
- "좌측 아이콘/이미지 + 제목 + 우측 보조정보·화살표"의 일관된 구조를 유지한다.

### 5.6 하단 탭

- 4~5개 이내, 아이콘 24px + 라벨 10~11px.
- 선택 상태는 Primary 파란색, 비선택은 grey500.

## 6. 문구(카피) 규칙 — 토스 문법

- **친근한 존댓말**: "~했어요", "~할게요" (예: 이체했어요, 저장했어요). 안내는 "~해 주세요".
- **한 문장에 한 가지 정보**. 불필요한 수식어는 삭제한다.
- **겁주지 않기**: "실패했습니다", "금지" 대신 "다시 시도해 주세요"처럼 다음 행동을 알려준다.
- **숫자는 아라비아 숫자 + 쉼표**: `1,234,567원`. 단위는 한글(원·개·명).
- **날짜·시간 형식 통일**: 예) 2025.01.15, 14:30.
- **오류 안내 3요소**: 무슨 일이 있었는지 + 왜인지 + 어떻게 하면 되는지.
- 버튼·메뉴는 2~4음절로 짧게, 화면 제목은 명사형으로.

---

## 7. 아이콘·일러스트

- 아이콘은 같은 그리드·굵기로 세트를 맞춘다(기본 24px 기준).
- 일러스트는 밝고 단순하게, 브랜드 파랑을 포함한 제한된 팔레트만 사용.
- 감정 표현(이모지·캐릭터)을 적극적으로 써 금융의 딱딱함과 두려움을 낮춘다.

---

## 8. 모션

- 전환 애니메이션은 짧게(200~300ms), ease-out 위주로 자연스럽게.
- 화면 전환보다 로딩 속도가 우선. 불가피한 대기에는 스켈레톤 UI를 보여 준다.
- 성공·완료 순간에는 가벼운 피드백(체크 애니메이션 등)을 준다.

---

## 9. 접근성·품질 기준

- 최소 터치 영역 44×44pt 이상.
- 텍스트 명암 대비 WCAG AA(4.5:1) 준수.
- 최소 화면 너비(360px)에서 레이아웃이 깨지지 않게 한다.
- 색상·간격·글자 크기는 하드코딩 대신 토큰으로 관리해 일관성을 유지한다.

## 10. 적용 체크리스트

- [ ] Primary 파랑이 한 화면에 하나인가?
- [ ] 간격이 모두 4px 배수인가? 좌우 여백 24px인가?
- [ ] 텍스트 위계가 명도(회색조)로 구분되어 있는가?
- [ ] 문구가 해요체이고, 오류 안내에 다음 행동이 담겨 있는가?
- [ ] 색상·타이포·간격이 토큰(상수)으로 정의되어 있는가?
- [ ] 최소 화면 너비(360px)에서 확인했는가?
